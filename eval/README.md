# Eval harness for tiered fastText ONNX models

`run_eval.py` measures how well a derived tier model (`fluency`, `mini`)
preserves the ranking behaviour of its full-model parent and gates release
on the measured numbers. Thresholds live in `gates.json`; reports are
written to `eval/reports/{lang}.{tier}.json` and are committed.

## Metrics

### rank_corr (gated)
2000 probe words are sampled across 20 equal rank buckets spanning ranks
50-30000. For each probe, 3000 comparison words are drawn uniformly from the
full vocabulary; comparison words the tier cannot embed (outside the mini
vocab) are dropped from **both** score vectors, so full and tier are scored
on identical word sets. Each model cosine-scores the probe against the
comparison set; the two score vectors are compared with Spearman rank
correlation (`scipy.stats.spearmanr`). The reported value is the mean over
probes.

### top1_agreement (gated, proxy)
400 probe words with rank 1000-30000 each get one deterministic
single-edit typo from the keyboard-aware generator in `noise.py` (below).
The typo must itself be in vocabulary (and inside the tier vocab) so both
models can embed it; probes whose typo never lands in vocab after 50
attempts are skipped and counted. The candidate set is the true word plus
the top-20 nearest neighbours of the typo under the **full** model
(cosine, over a 20000-word sample window for speed). Candidates outside
the tier vocab are dropped from both models' ballots. Each model scores
candidates by cosine to the typo; agreement is the fraction of probes
where both argmax to the same word.

## Typo model (`noise.py`)

Typos are generated by `noise.make_typo(rng, word, lang)` — a
MULTYPO-style (arxiv 2005.01158) keyboard-layout model for Latin/Cyrillic/
Greek languages and a curated character-confusion model for CJK. The physical
key maps are mirrored from the kotoshu gem's own layout files
(`lib/kotoshu/keyboard/layouts/*.rb`), which are the source of truth; a
"neighbor" is a key at Manhattan distance 1 or 2 on the gem's [row, col]
grid, with distance-1 keys weighted 3x distance-2 keys. The tr/uk/el grids
are curated standard national layouts living in `noise.py` itself (the gem
has no layout files for them yet; mirror them from the gem and delete the
local copies when it grows them).

| language | script model | supplement |
|----------|--------------|------------|
| en       | QWERTY       | -          |
| es, pt   | QWERTY       | dead-key diacritic slips (á/é/… , ñ, ç, ã) to/from the base letter |
| de       | QWERTZ (umlaut + eszett keys ä/ö/ü/ß are physical keys) | spelling slips a<->ä, o<->ö, u<->ü, s<->ß |
| fr       | AZERTY (ù key) | dead-key slips é/è/ê/ë, à/â, ç, î/ï, ô, û to/from the base letter |
| ru       | JCUKEN (ё key) | е<->ё slip |
| it, nl   | QWERTY | dead-key slips (it: à è é ì ò ù; nl: é ï ö ü in loanwords) |
| pl       | QWERTY | dead-key slips ą/ć/ę/ł/ń/ó/ś/ż/ź to/from the base letter |
| ro       | QWERTY | ă/â/î/ș/ț slips |
| sv       | QWERTY | å/ä/ö slips |
| da       | QWERTY | æ/ø/å slips |
| ca       | QWERTY | à/é/í/ó/ú/ç slips |
| vi       | QWERTY | Vietnamese diacritic slips (a-family ă â à á ả ã ạ, e/o/u/y tone sets, đ) |
| cs       | QWERTZ | háček/acute slips ě/š/č/ř/ž/ý/á/í/é/ú/ů (plus ď/ť/ň) |
| hu       | QWERTZ | acute/umlaut/double-acute slips á/é/í/ó/ö/ő/ú/ü/ű |
| tr       | Turkish-Q grid (curated in noise.py — the gem has no tr layout file yet): ı ğ ü ş i ö ç are physical keys | dotted/dotless i slip, ô/û |
| uk       | Ukrainian ЙЦУКЕН grid (curated in noise.py): і ї є ґ are physical keys | - |
| el       | Greek phonetic grid (curated in noise.py; standard EL layout is phonetically equivalent) | accent slips ά/έ/ή/ί/ό/ύ/ώ, final-sigma σ<->ς |
| ja       | curated kanji/kana visual confusions (未/末, 士/土, シ/ツ, ソ/ン, …) | adjacent-char transposition fallback |
| ko       | curated jamo confusions inside Hangul syllables (ㅐ/ㅔ, ㅒ/ㅖ, y-vowel slips, shape flips, ㄱ/ㅋ …) | adjacent-char transposition fallback |
| zh       | curated shape-similar hanzi confusions (己/已, 日/曰, 未/末, …) | adjacent-char transposition fallback |

Layout languages draw one of substitute (neighbor of the substituted
char, weight 0.40) / insert (neighbor of the adjacent char, 0.20) /
delete (0.20) / transpose (0.20); CJK draws confusion-substitute (0.65) /
transpose (0.35), or transposition only when no character of the word is
in a confusion pair. **The CJK confusion sets are curated by hand from
well-known proofreading confusion lists, not learned from data** — they
are a stand-in until a confusion matrix can be measured from a real CJK
typo corpus. Randomness comes only from the harness's seeded generator
(`default_rng([42, crc32(language)])`), so the typo stream is
reproducible.

**Caveat:** this is a proxy for the gem's real spelling-correction rerank
pipeline, not the pipeline itself. The real candidate generator and any
string-prior the gem applies are not modelled here. The report JSON carries
this in `metric_note`.

**Gem conformance slot (kotoshu-rs M3):** when the gem ships conformance
vectors, place them at `eval/conformance/{lang}.json` and score tier outputs
against them; they supersede `top1_agreement` as the release gate. The
harness entry point is `evaluate()` in `run_eval.py` — add a
`conformance` metric alongside the existing ones rather than replacing the
proxy, so historical reports stay comparable.

### coverage (reported, not gated)
Frequency-weighted vocabulary coverage with weight `1/(rank+1)` over the
full vocabulary. The full tier coverage is 1.0 by construction; a 30k-prefix
vocab covers roughly 0.90.

## Real-typo corpus benchmark (report-only, not gated)

`scripts/fetch_corpus.py` downloads the GitHub Typo Corpus v1.0.0
(Hagiwara & Mita, LREC 2020; 350k+ human typo corrections, MIT) into
`eval/corpora/` (gitignored) and extracts deduplicated (typo, correction)
pairs for the 9 languages. The official S3 bucket has been decommissioned,
so the script falls back to a Wayback Machine snapshot of the exact
original URL; the release publishes no checksum, so the script pins a
self-recorded sha256 to guard re-downloads.

`eval/corpus_bench.py` then measures, per language and per tier (full /
fluency / mini), how well the model ranks the human correction among its
entire vocabulary by cosine similarity to the typo (top-1 / top-5 / top-20
hit rates). Only pairs where both words are in the **full** vocabulary are
kept (the embedding side can only score words it can embed); a tier
additionally skips pairs whose typo or correction is outside its own
vocab (counted as `typo_oov` / `correction_oov`). Pair counts are small
for non-English languages (the corpus is GitHub commits, ~94% English):
they are reported as-is, per language. Reports land in
`eval/reports/corpus.{lang}.json` (committed; the corpus itself never is).
Report-only in v1 — it becomes the full correction-pipeline benchmark
once kotoshu-rs conformance vectors exist (plan 67 M3).

## Determinism
All sampling uses `np.random.default_rng([42, crc32(language)])` (PCG64).
Given the same model pair, reports are reproducible apart from the
`generated_at` timestamp. Both tiers of a language draw the same probe
sequence, so their metrics are comparable.

## Gates (`gates.json`)

| tier    | top1_agreement | rank_corr |
|---------|----------------|-----------|
| fluency | >= 0.95        | >= 0.97   |
| mini    | >= 0.85        | >= 0.90   |

Gates are never weakened. `scripts/build_tiers.py` may only climb its
recipe ladder and records every attempt in the report.

## What the eval decided (2026-09-02, en)

The original recipes cut size with SVD dimensionality reduction
(300→128/144/160 for fluency, →64 for mini). Measured on en, every one
of them failed the fluency gates badly — rank_corr 0.87-0.91 vs the
0.97 gate, top1 0.69-0.76 vs 0.95 — because fastText neighbour
rankings do not survive projection to a low-rank subspace. The recipes
that pass are **full 300 dims + int8 per-row quantization + vocabulary
truncation**: fluency keeps the top 50k words (~15 MB) and mini the
top 10k (~3 MB), scoring rank_corr 0.9999 / top1 1.0000 on the words
they keep. Vocabulary loss is reported separately by the coverage
metric rather than hidden inside the gated metrics — rank_corr and
top1 only score comparison words both models can embed, by
construction (see above).

So: size comes out of the vocabulary and the byte width, never the
dimensions. The eval reports in `eval/reports/` carry the full ladder
history including the failed SVD attempts.

## Usage

```sh
python3 eval/run_eval.py --lang en --tier fluency --repo-root .
python3 scripts/build_tiers.py --lang en de --repo-root .
python3 scripts/build_tiers.py --all --repo-root .

# real-typo corpus benchmark (download once, then offline)
python3 scripts/fetch_corpus.py --repo-root .
python3 eval/corpus_bench.py --all --repo-root .

# typo generator smoke test (deterministic per-language typos)
python3 eval/noise.py
```

Both gate scripts exit nonzero when a gate fails.
